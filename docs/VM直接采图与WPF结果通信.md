# AxisLab 模拟相机直接连接 VM（2.1，无 WPF 依赖）

本版由 AxisLab 自己启动和管理虚拟 GigE 相机。旧文件名保留以兼容已有文档链接，不再以 WPF 为入口。

## 软件采图与算法调试

1. 在 AxisLab 添加或选择模拟相机，设置安装位置、内参及分辨率。保持渲染窗口打开。
2. “相机 / VM 直采”选相机和本机网卡，发布虚拟 GigE 相机。
3. 在 VM 4.3 相机管理连接 AxisLabCam，序列号 AXISLAB001；图像源使用相机模式。
4. 设 TriggerMode=On、TriggerSource=Software。由 VM 运行图像源/视觉流程，会触发 AxisLab 渲染并采到实际模拟视野。
5. 直接在 VM 编辑 BLOB、模板匹配、N 点标定、手眼与坐标转换模块。无需 WPF，也无需 AxisLab.VmDirectLink.dll 才能采图。

## 光电模拟触发

1. 在 AxisLab 光电属性绑定停带设备与触发相机，或通过取放生成器自动绑定。
2. VM 相机设 TriggerMode=On、TriggerSource=Line0，先让 VM 进入采图等待。
3. 再启动 AxisLab 传送带/工作单元。物品进入检测区产生 DI 上升沿，AxisLab 停带并进行一次曝光。
4. 同一个曝光通过虚拟 GigE 发给 VM。不会用旧图像补成功；没有新边沿时 Line0 不自行产生图像。
5. 切换触发源、重启采集或换相机后，先重新确认接收等待，再触发工件。

这是软件时间步驱动的 Line0 模拟，不是实际电气脉冲或微秒级硬触发。当前内部示教取放只等待 AxisLab 图像完成，不等待 VM 算法结果；如果需要按检测结果运动，可在内部流程空闲后由 VM/PLC/C# 经 Modbus 7/8 发送坐标，或按后续阶段扩展内部握手。

## 标定数据与坐标

AxisLab 负责装置运动、相机仿真与姿态记录；VM 负责检测、标定求解和坐标转换。相机可独立安装，也可挂载到机器人法兰/TCP。

AxisLab 相机页导出的标定观测包含 frameId、PNG SHA-256、曝光时间、分辨率、相机配置修订、机器人关节和法兰/TCP 矩阵，不含相机安装真值/内参。另存同帧 PNG 后，可对应到自己的 VM 标定数据。

固定相机 N 点标定需要正确配对图像特征和物理点。若靶标原点与 TCP 不重合，要处理工具安装偏置。空间手眼应采集多个姿态和独立验证样本，不能用平面九点替代完整手眼，也不能用仿真真值代替视觉求解。

## 接口与已知范围

单路、Mono8、同机回传，标准 GVCP 控制端口 3956。已验证 tun0 接口；WLAN 过滤驱动可能无法接收同机发送图像。一个场景可放多台相机，但一次只发布一个虚拟 GigE 实例。变更分辨率/相机安装或切换工程会停止本实例，重新启动并更新 VM 标定。

如果 3956 已被旧 WPF/相机服务占用，在原入口停止该实例，再由 AxisLab 发布；软件不会强制终止其他相机或更改网卡、驱动、防火墙。

本轮自动集成测试使用隔离端口的协议接收端验证了光电 → 真实渲染 → Line0 图像流、曝光身份及 SHA-256，未操作使用者当前 VM 方案。VM 4.3 的软件采图在此前阶段已验证；新 Line0 模式仍需按本机 VM 图像源配置进行现场联调。
