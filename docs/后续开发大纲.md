# 后续开发大纲

当前基线 2.0：去除积木编程和 WPF SDK 模式，统一两个应用的源码、发布包和入口。已确认主链路为 AxisLab 相机 → VM 采图/检测/标定/坐标转换 → WPF 接收并控制 AxisLab。

| 阶段 | 开发目标 | 验收结果 |
| --- | --- | --- |
| 8A：当前统一版本 | 明确分工、清理旧入口、VM 基坐标结果协议、采样导出、统一构建和 GitHub 发布 | 仿真器/上位机独立运行；WPF 无 SDK 依赖；保留手动与示教；协议和操作说明可用 |
| 8B：VM 流程落地 | 在用户实际 VM 4.3 环境制作采样、N 点求解、一般工件 XY/方向流程；流程输出配置与标定文件管理 | 自定义工件位置/角度改变后，VM 重新采图定位；独立验证点误差留档；WPF 到达正确目标 |
| 9：设备流程编排 | WPF 加入可配置的动作步骤、条件、超时、重试、暂停、停止；远程触发 VM 流程并关联请求 | 一键执行一个受控设备循环；不在 AxisLab 内恢复旧积木编辑器 |
| 10：传送带与光电 | 输送、工件生成、光电传感器、停带与稳定时间、相机触发、运行状态通信 | 首个案例采用光电触发停带 → 稳定拍照 → 抓取；失败工件可复位 |
| 11：夹爪与工位抓放 | 夹爪状态、附着/释放工件、工位坐标、物料占用、完整抓放步骤 | 从传送带抓取工件，放到指定工位；流程由 WPF 控制 |
| 12：标定扩展 | 多相机直采、相机管理、完整空间手眼、工件/工位坐标、误差/噪声模型、样本复盘 | 以独立样本验证空间精度；多个相机、机器人和工位不混帧、不混坐标 |

需求边界：

- VisionMaster 始终负责视觉算法和坐标转换；WPF 负责设备控制、动作流程、数据记录。
- AxisLab 的场景拖拽、设备添加、尺寸配置、相机和教学继续保留。
- 新可视化设备编程界面另行设计，不能把当前已删除的积木当作目标。
- 九点平面标定与空间手眼分开验收；训练数据不直接使用相机真值。
- 当前虚拟相机是单路实验实现，硬件精准触发、真实工业驱动兼容性和多个同时枚举需要专项验证。
